### 4. [Ephemeral-AI-Lab/layerfs](https://github.com/Ephemeral-AI-Lab/layerfs) · ⭐ 1,919 · Rust · MIT

被 1 位大牛 star：Tobi Lütke（tobi），2026-10-22。

给 Agent 用的临时可写文件系统：每次工具调用拿到一棵完整可写的文件树，改动存成 commit，卸载时丢弃的是临时 overlay 而不是历史。

要点：分支模型是这套设计的重点——Agent 各自 fork 分支并行工作再 merge，冲突默认拒绝，除非用 `.lww` 规则放行最新写入。存储层用 SQLite 保存分支、commit 与内容对象，内容分块去重，再通过 FUSE 把「已提交的树 + 本地 overlay」暴露给进程。这套「共享历史 + 检查点 + 回退/合并」的思路，与 Git 之于多人协作是同一类问题的解法。

### 5. [pgrundev/pgx](https://github.com/pgrundev/pgx) · ⭐ 351 · Rust · AGPL-3.0

被 1 位大牛 star：Tobi Lütke（tobi），2026-10-22。

用 Rust 写的轻量 Postgres，专供 AI agent、CI、PR 预览这类「用完就扔」的隔离数据库。

要点：一个进程内共享不可变状态，按数据库名、角色与限额互相隔离，官方称 4 vCPU / 8 GB 机器上可支撑 1,000 个隔离库、空闲每库约 70–128 KB。在 ZFS 这类 copy-on-write 存储上从封存模板克隆，10 GB 模板约 674 ms 完成分支、额外占用约 13.6 MB。说的是 PostgreSQL wire protocol 与 SQL 方言，官方列出 Rails、Django、Prisma、SQLAlchemy、node-postgres 兼容。当前是 v0.1.0，定位在可抛弃负载，不是崩溃安全的主库。
