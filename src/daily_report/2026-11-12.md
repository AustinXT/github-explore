## 📌 今日导读

今天的日榜从昨天的 12 席缩到 10 席，5 进 7 出。席位数本身不是看点，看点在于**留下的 10 席里有 8 席与 AI 相关**（采集脚本的关键词启发式判出 6 席，另有 2 席人工兜底），而 5 个新进榜的项目里有 3 个是 Agent 基建：Chrome 团队的 Web 平台指南源码仓库排在第 3、shadcn 的代码审计技能包排在第 4、OpenAI 的 codex-security 排在第 9。榜首 meta/astryx 则连续第 2 天守住第 1。

第一个看点在新增结构。昨天日榜的 12 席里有 9 席与 AI 相关，今天是 8 席——AI 占比从 75% 抬到 80%，榜单反而更「纯」了。更值得注意的是新进榜的三个 Agent 基建项目分属三个不同厂商：Google Chrome 团队交付 Web 平台规范给 Agent 读，shadcn 交付「只审计不写码」的技能包，OpenAI 交付漏洞扫描 CLI。这三家上周都还在榜外，本期同时挤进前十——Agent 基建正在从「各自的小工具」变成日榜的默认构成。

第二个看点在安全线，这是本期最硬的一条。榜内 OpenAI 的 [openai/codex-security](https://github.com/openai/codex-security) 今日新进榜第 9，是 OpenAI 首次公开自己的漏洞扫描 CLI 与 TypeScript SDK；榜外 11-11 早上 [modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers) 发了 v2.4.0，**一次修掉 6 个漏洞**——filesystem 服务器的 TOCTOU 越界读、git 服务器的 `.git/config` 命令执行、fetch 服务器的 IPv6 与 robots.txt 绕过，两个方向同时收紧。MCP 官方服务器和 OpenAI 自己的安全工具在同一天各推进一步，这已经不是巧合。

第三个看点在榜外与外部动态。[qwenlm/qwen-code](https://github.com/qwenlm/qwen-code) 发了 v1.0.0-preview，把 Qoder 的能力合并进来并提供免装 Node.js 的原生包；[a2ui-project/a2ui](https://github.com/a2ui-project/a2ui) 出了 v1.0 稳定版，把「Agent 流式生成原生 UI」定成正式协议；[DIYgod/pinky](https://github.com/DIYgod/pinky) 则是 11 月 6 日才建仓的新项目，11 天涨到 1,889 星，做的是让任意 Agent 经 MCP 操作真机手机。

### 1. [openai/codex-security](https://github.com/openai/codex-security) · ⭐ 11,575 · TypeScript · 日榜第 9（新进榜）· 评分 7.1

OpenAI 首次公开自己的漏洞扫描 CLI 与 TypeScript SDK，用于发现、验证并修复代码里的漏洞。

要点：npm 包 `@openai/codex-security`，全局安装后用 `cs` 命令（等价于 `codex-security`），要求 Node.js 22.13+ 或 24.x/26.x、Python 3.10+，先跑 `cs login`；扫描用法有 `cs scan .`、`cs scan . --path src --path tests`、`cs scan . --diff origin/main`、`cs scan . --mode deep`（在标准扫描之上重复分析并去重）、`cs scan . --max-time 15`（限时调查）；结果用 `cs scans show` 查看，`cs export --scan SCAN_ID --artifact threat-model --output threatmodel.md` 导出，支持 SARIF / JSON / CSV，CI 侧直接用 SARIF；`cs policy .` 在仓库外生成 SECURITY.md 草稿与威胁模型；后端不止 OpenAI，还支持 Amazon Bedrock、OpenRouter、Fireworks AI，CI 用 `OPENAI_API_KEY` 或 `CODEX_SECURITY_API_KEY`，发现可跟踪到 Linear、Jira、GitHub；TypeScript SDK 是 `const security = new CodexSecurity(); await security.run("/path/to/repo"); await security.close();`，扫描会读取仓库根目录及组件级 SECURITY.md 作为指导。

**今天最值得记的一条：OpenAI 把「扫漏洞」做成了独立可安装的 CLI，而不是塞在 IDE 插件里。README 明确没有说明内部的发现算法与验证机制，也没提沙箱或 PoC 利用——「验证」这一步目前仍是黑盒，这是它区别于传统 SAST 工具的地方，也是它目前最薄的地方。**

### 2. [shadcn/improve](https://github.com/shadcn/improve) · ⭐ 10,671 · 日榜第 4（新进榜）· 评分 7.0

只做审计与出计划、不改代码的 Agent Skill，把强模型的判断力换成廉价模型的执行力。

要点：五步流程——Reconnaissance（摸清技术栈与构建/测试/lint 命令）→ Audit（正确性、安全、性能、测试、技术债、依赖迁移、DX、文档、未来方向共九类）→ Verification（复核每条结论，并把被否掉的误报也记下来）→ Prioritization（按影响/成本/置信度排序）→ Planning；安装用 `npx skills add shadcn/improve`，兼容所有支持 Agent Skills 格式的 Agent，输出是 `plans/` 下的 Markdown（如 `plans/001-fix-n-plus-one.md`），含索引、执行顺序与依赖图，可直接交人或其他模型执行；命令族包括 `/improve`、`/improve quick`、`/improve deep`、`/improve security`、`/improve branch`、`/improve next`、`/improve plan <描述>`、`/improve review-plan <文件>`、`/improve execute <plan>`、`/improve reconcile`，加 `--issues` 可把计划发布为 GitHub issue；强弱模型分工是它真正的设计——强模型负责侦察、审计、评估与写规格，`/improve execute` 在隔离的 Git worktree 里起廉价执行模型实现并回审，可要求返工至多两轮或直接否决改计划，合并仍由人决定；技能自身只写 `plans/` 目录，MIT 许可。

**「先审计出计划、再让便宜模型去改」正在变成一类标准技能包——它和今天榜上的 codex-security 是同一条思路的两端：一个是让强模型只输出计划，一个是让强模型只输出安全结论，都不碰代码。**

本站尚未做过深度分析。

### 5. [modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers) · ⭐ 91,938 · 榜外发版 · v2.4.0 · 11-11 07:07 · 评分 6.7

MCP 官方服务器 v2.4.0：一次修掉 6 个漏洞。

要点：`@modelcontextprotocol/server-filesystem` 升到 2.3.0——读取操作改为相对「被校验过的目录」打开文件，堵住「校验后目录被换成 symlink」的 TOCTOU 越界读，FIFO/socket/设备文件直接拒绝；`move_file` 只移动它校验过的源——先在同设备内把源文件改名移出校验目录，源目录被换成 symlink 也无法把外部文件带进允许范围；`mcp-server-git` 2026.11.11——仓库自身 `.git/config` 里的 `core.fsmonitor`、`diff.external`、hooks、filter/merge driver、签名配置不再能以服务器权限执行命令，Git 低于 2.31 直接拒绝；`mcp-server-git` 的 `--repository` 隔离扩展到 `objects/info/alternates`、linked worktree 与 Git 目录内的 symlink（Windows 目录联接尚未覆盖）；`mcp-server-fetch` 2026.11.11——`fec0::/10` 被正确判为私有地址，`2000::/3` 之外的 IPv6 一律拒绝，robots.txt 同时按路径原样与解析后路径匹配，`//private`、`/x/../private` 无法绕过 Disallow；TypeScript 服务器从日期版本号（2025.x/2026.x）改为语义化版本，需手动 `npm install @modelcontextprotocol/server-filesystem@2.3.0` 才会升级。

**这一版没有新功能，全是安全修复，而且修的都是「校验与使用之间隔了一道」的那类漏洞——TOCTOU、symlink 换目录、`.git/config` 执行命令。MCP 官方服务器自己也在被当成攻击面来审，这是生态成熟的标志。同时改版本号策略是另一个信号：官方开始按 semver 管理 MCP 服务器，依赖它的人要盯着自己锁的版本。**
