### 1. [Tencent-Hunyuan/Hy4-flash](https://github.com/Tencent-Hunyuan/Hy4-flash) · ⭐ 59 · Python · 11-17 建仓、11-18 04:24 UTC 首次推送 · 开放权重（非 GitHub Release）· 评分 7.6

**今天唯一一条「今天才发生」的大新闻：220B 的开放权重 MoE，每 token 只激活 12B。**

要点：总参数 220B（含 64B Engram），每 token 激活 12B，原生接受图文输入、只生成文本，上下文上限 1M tokens；42 层语言主干由 1 层 dense FFN + 41 层 MoE 组成，用 identity Hyper-Connections（iHC）打通层间信息流；视觉侧是改造自 SigLIP2-So400m-Patch16-Res512 的编码器 + MLP projector 接入主干；**相对 Hy4 的三处架构改动**——稀疏注意力（IndexPool）与滑动窗口注意力（SWA）按 1:3 交替、LatentMoE 让路由专家在更低维的隐空间里工作（512 个路由专家每 token 激活 16 个，另加 1 个共享专家）、Engram 机制；官方称这套组合把 KV cache 压到 **Hy3 的 1/24、Hy4 的 1/6**；内置 5 层、0.85B 的 DFly2 投机解码 drafter（用 AngelSpec 训练），每个 draft 层与目标模型的稀疏注意力层共享 KV cache（KV Share）和压缩索引器选出的至多 2,048 个位置（Index Share）；权重分 **Hy4 flash / Hy4 flash-FP8 / Hy4 flash-base**（base 是预训练底模，非指令模型）三个版本，同时上架 Hugging Face、ModelScope 与 GitCode；提供 Transformers、OpenAI 兼容 API、vLLM、SGLang 部署与量化路径，另有第三方 GGUF 转换（暂未合入 transformers 主干，需按 README 指定的 commit 安装）；许可为 Tencent Hy License。官方自述数据：WorkIndex 得分 42.1（Hy4 preview 39.7），平均每任务成本为 Hy4 preview 的 1/13、Hy4 的 1/20；盲测用户满意度 2.79/4（Claude Haiku 5.5 为 2.81/4），中位端到端完成时间 6.7 分钟，每任务 0.26 元；官方建议用它做深度检索、文档处理、幻灯片、简单前端 demo 与 computer use，长程软件工程仍推荐 Hy4。

**把「220B」和「12B」并排放，才看得出这次开源的分量**——它卖的不是最大，而是「每任务成本 1/13」这个能落到账上的数字。而 KV cache 压到 1/24 才是 1M 上下文能跑起来的前提：长上下文推理的成本几乎全在 KV 上。

### 3. [appwrite/appwrite](https://github.com/appwrite/appwrite) · ⭐ 58,182 · TypeScript · 日榜第 13（本地 423 天日榜快照首次上榜）· 2.7.3（11-17 12:55 UTC）· BSD-3-Clause · 评分 6.8

**一个 2019 年的 BaaS，把自己的首页第一句改成了「给 Agent 和开发者的开源云」。**

要点：README 首句现为「The open-source cloud for agents and developers」，并明确写出是 **MCP and agent-first** 平台；**托管 MCP server 走 OAuth，Agent 不需要自己创建或管理 API key**（`https://mcp.appwrite.io/`，自建实例用 local MCP server），README 直接给出 Cursor、Claude Code、Codex、VS Code 的 `mcpServers` 配置；另有 `npx skills add appwrite/agent-skills` 装技能包，让模型生成正确的 SDK 调用，还能生成 `AGENTS.md` 与快速上手提示词；架构图把 **Console / Flutter / iOS / Android / Web / Agents / MCP / CLI / SDKs / Terraform** 并列成同一层的接入面；配套仓库 `appwrite/agent` 是基于 LangGraph 的**无状态 Agent 运行时**（Cloud 侧 `/v1/agent`，2026-07-31 建仓）——one-shot 路由 + platform/researcher/planner 三个 ReAct 子 Agent，自研 **Console 协议（`appwrite.console/v1`）** 让 Agent 向 Console 下发主题、导航、toast、资源卡片、列表与用量图表，自研 **Clarify 协议（`appwrite.clarify/v1`）** 让 Agent 在缺信息或删除操作前发结构化追问（选择/确认/文本），工具含 calculator、current_time、web_search、browser_fetch、http_get、appwrite_skill、sandbox_exec（桩）、console、clarify、memory 加上本轮凭据带来的 MCP 工具，**默认不给模型宿主 shell**；`appwrite/skills`（原 agent-skills）11-18 有合并；发版侧 2.7.3（11-17）是重建 `appwrite/base` 2.2.12（Alpine 当前包、libpq 18.7）并把 `openruntimes/executor` 从 1.3.1 升到 1.3.5 以清掉镜像公开漏洞，升级不需改 schema；再往前的 2.7.2（11-12）是覆盖 auth、滥用限额、存储、realtime、消息、函数、VCS 与代理的安全补丁；11-18 当天 Console 侧合并了 Videos（对齐 Stream v8 API 与 Console SDK）、Git automation（含 Gitea 用例测试）、drones 卡片改标为 prompts、factory hero 渲染性能优化，以及把 rendition 默认保留时长降到 12 小时。

**Appwrite 真正的动作不是「加了个 Agent」，而是把 API Key 这个前置条件整个拿掉**——托管 MCP 走 OAuth、Agent 运行时无状态、Console 与 Clarify 两个自研协议让 Agent 能反过来指挥界面。**一个 BaaS 想接住 Agent，必须先让 Agent 不用管凭证、不用管会话、不用猜界面该长什么样。**

### 4. [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino) · ⭐ 11,285 · C++ · 日榜第 14（本地 423 天日榜快照首次上榜）· Apache-2.0 · 评分 6.6

**它不是发了个版本，而是把一天的提交全押在了「LLM 解码该在哪跑、怎么跑快」上。**

要点：11-18 当天的提交几乎条条冲着 LLM 推理去——**[NPUW] GQA: detect V2 by u2 weights before position_ids**（#39978，u2 权重压缩下的 GQA 判定）、**[GPU][CPU][CORE] Expose PagedAttention block size on compiled model**（#37928，把 PagedAttention 的块大小暴露到编译后模型上）、**[GPU] Do not pad 2-4 row int4 fully connected to 16 rows**（#38795，修掉 int4 小 batch 被强行补齐到 16 行的浪费）、**[GPU] Support BF16 for Topk**（#39655）、**[GPU][MLIR] Add Gelu (v0/v7, erf/tanh) converter**（#39834）、**[NPU] Decode an unbounded dimension of an imported blob as fully dynamic**（#39559）、**[NPU] Fix debatch issue and validate batch size on import path**（#39950）、**[GPU] Fix align_corners Interpolate mismatch between static and dynamic shapes**（#39758）；往前一天还有 **[GGUF] Add adapt_to_genai entry point returning GenAI models**（#39783，把 GGUF 权重直接转成 GenAI 模型）、**[CPU][ARM] Up to 2x faster GQA decode attention: share u8 key/value rows across query heads**（#39424）、**[NPUW] Do not use shared vocabulary for Whisper**（#39929）、**[CPU][ARM] Fix NaN in f16 softmax for all-negative score rows**（#39262）；11-16 则补上了 **Qwen3.5 纯文本导出的 position_ids 处理**（#39652）；最新正式发版是 2026.4.1（2026-10-01）；README 主打「用 PyTorch / TensorFlow / ONNX / Keras / PaddlePaddle / JAX 训出来的模型，转成 OpenVINO IR 部署到 CPU（x86/ARM）、GPU（Intel 集显与独显）与 Intel NPU」，GenAI 能力另有 `openvino.genai` 仓库。

**这批改动的共同点，是它们都不在「让模型更快」，而在「让模型的形状、精度和内存布局在目标硬件上说得通」**——u2 权重要先判 GQA 版本、int4 的 2–4 行不能被补成 16 行、编译模型要能暴露 PagedAttention 块大小。GGUF 那条入口尤其关键：它意味着社区里现成的量化权重可以不经过「转 ONNX」这一步直接进 GenAI。

### 5. [mastra-ai/mastra](https://github.com/mastra-ai/mastra) · ⭐ 29,621 · TypeScript · @mastra/core@1.84.0（11-18 10:36 UTC）· 评分 6.6

**它把「长流程的状态怎么存」和「进程崩了谁来接手」当成同一个问题来解。**

要点：引入 **Storage Version 2**——run 不再整体序列化，而是拆成 header + 按 step 的行，长流程只写增量，官方示例里发布体积从 98 MB 降到 11 MB、实写从 75 MB 降到 3.1 MB；工作流的**崩溃恢复循环**随 `startWorkers()` 自动启动，用跨实例的 leader election lease 去接管崩溃掉的那个默认引擎 run；恢复逻辑改成了 broker-aware——在 Redis/Valkey Streams 与 Google Cloud Pub/Sub 下让 broker 重投未确认的 step，避免同一步被并发重复执行；Knowledge 新增 `movePage()`（移动页面同时保留 ID、embedding 与链接）与可断点续跑的 `reembed()` 批量重嵌入。

**「只写增量」和「跨实例 leader election」放在一起看，才知道它解决的是生产环境的两个真问题**：状态越写越肥会让存储先崩，而 Agent 进程被抢占或 OOM 杀掉之后，谁来接着跑最后一轮才是长流程能否上生产的前提。broker-aware 的重投处理说明它已经考虑过「重投 = 重复执行」这个分布式经典坑。
