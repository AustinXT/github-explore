### 1. [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio) · ⭐ 85,993 · Python · 日榜第 3（30 天内第 11 次上榜）

全本地语音工作台：声音克隆、声音设计、视频配音、听写转写、有声书制作一条龙，覆盖 646 种语言。30 天净涨 46,920 星（39,073 → 85,993），是本期增量最大的项目。

要点：功能分 Create / Produce / Connect 三栏——克隆或设计声音、带时间轴的视频配音、悬浮窗听写，以及给 Agent 用的本地 API 与 MCP；工作流全跑在本地硬件上，远端服务只是可选项，使用统计需显式同意；硬件覆盖 NVIDIA CUDA、Apple Silicon Metal（MPS）、AMD Vulkan 路径（CosyVoice GGUF）与纯 CPU 兜底（需装约 5 GB 的 PyTorch），Windows on ARM 仍是实验性、Intel Mac 只能开界面并接远端后端。它在 10-19 至 10-24 掉出榜单六天，今天重返即到第 3。

### 2. [makecindy/cindy](https://github.com/makecindy/cindy) · ⭐ 4,555 · TypeScript · 日榜第 1（昨日第 10 · 2 次上榜）

本地运行的跨端 AI 代理客户端，「Consider it done」——把 harness、模型和工具收进一个 agent，直接在你自己的电脑上干活。一天升 9 位登顶，是本期排名移动最大的项目。

要点：首批支持 Claude Code 与 Codex 两种 harness，模型与 harness 可自由混搭、任务中途切换，工作区、记忆、技能与工具都不丢；能驱动浏览器、电脑和手机，能从 IM 与定时任务里接活；pnpm monorepo——`apps/desktop` 是 Electron 桌面端、`apps/mobile` 是 Expo / React Native 移动端，`packages/*` 放认证、设备连接、agent 编排与模型 provider；模型接入四路并行：官方托管服务、复用已有的 Claude Code / Codex 订阅计划、自带 API Key、本地模型。Apache-2.0。

### 3. [Nutlope/hallmark](https://github.com/Nutlope/hallmark) · ⭐ 33,112 · CSS · 日榜第 2（昨日第 4 · 2 次上榜）

Together AI 出品的设计技能，给 Claude Code / Cursor / Codex / OpenCode 装上，专治一眼假的「AI 味」。单日再涨 1,485 星，重回榜二。

要点：48 套主题，每套是一份「材质」——纸、字体、颜色、表面、自带组件与纹理各成一体的成品页；质量闸分 Floor / Reflex / Finish 三级，Floor 永远不放行（对比度、焦点、reduced motion、编造事实、手机端布局），Reflex 是模型的默认惯性、有理由可记录在案地推翻，Finish 只管工艺细节不拦发布；明确点名并拦截机器感设计——每个标题上方的眉标签、加字距的大写标签、标题里单个彩色词、一页空框架或只有照片、hero 撑不满首屏；先出渲染图审 hero，再在真实浏览器里对着这些迹象 lint，最后由一个全新上下文的审阅者拍板。

### 4. [pbakaus/impeccable](https://github.com/pbakaus/impeccable) · ⭐ 87,187 · Rust · 日榜第 4（昨日第 6 · 30 天内第 8 次上榜）

jQuery UI 创始人 Paul Bakaus 把设计经验编码成 Agent 可消费的设计语言。30 天净涨 16,177 星，与 hallmark 构成同一个命题的两种答案。

要点：1 个技能 + 24 条命令 + 62 条确定性检测规则——这 62 条由 CLI 与浏览器扩展执行，不调 LLM、不需要 API Key；`/impeccable init` 把「受众、用途、约束、语气」等产品事实写进 PRODUCT.md，与表层视觉指令分开存放；命令分 polish、audit、critique、distill、animate、bolder、quieter 等，可 `pin` 成独立快捷方式。README 近期已从 20 条命令更新为 24 条。

### 5. [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents) · ⭐ 114,105 · Python · 日榜第 6（41 天后重返 · 上次在榜 09-14）

要点：四类分析师并行——基本面（财务与内在价值）、情绪（新闻标题、StockTwits、Reddit）、新闻（全球新闻与宏观）、技术（MACD、RSI 形态），各自用各的工具，全部报告到齐才进入研究辩论；再交给交易员与风险管理团队；底层是 LangGraph 编排，支持 checkpoint 续跑与持久决策日志；v0.6.0 按模型档位分 provider、决策按标的存档，并在 Yahoo 新闻源故障时改走 Yahoo 搜索读新闻；回测只看该分析日期当时已发布的数据。

### 8. [Nanbeige/Nanbeige4.3-33B](https://huggingface.co/Nanbeige/Nanbeige4.3-33B) · 外部开源 · 10-24 上线

BOSS 直聘 Nanbeige 实验室开源的 33B 稠密 Agent 编码模型，权重与许可全开。

要点：33B 稠密架构、BF16 权重、原生 524,288（512K）上下文，Apache-2.0；自评 Terminal-Bench 2.1 得 80.9，同表对照 Qwen3.8-27B 为 73.0、Muse-Glimmer-30B 为 61.8、Gemma4-31B 为 47.2，Terminal-Bench 4.0 为 23.8（对照 6.3 / 1.6 / 0.0），DeepSWE 得 65.5（对照 42.5 / 4.4 / 2.7），评测用 mini-swe-agent v2.4.6；chat 模板默认开启 thinking，多轮工具调用建议 `preserve_thinking=true`。注意：这一版只有 HuggingFace 权重仓库，GitHub 上没有对应仓库。

### 9. [zhangshuibai/molten](https://github.com/zhangshuibai/molten) · ⭐ 5 · Rust · 外部开源 · 10-25 建仓

不依赖 Python 的原生推理引擎，用 Rust + Metal 在 Mac 上跑 LiquidAI LFM2.5-24B-A2B。

要点：单文件约 6 MB，只链 macOS 系统框架，无需 PyTorch 或 MLX；M5 Max 上解码 300+ tok/s，比 mlx-lm 快 1.45–1.6 倍、比 llama.cpp 快 1.3–1.5 倍，覆盖 256 到 128K 上下文区间；数值与 mlx-lm 逐 token 对齐，MATH-500 与 IFEval 分数复现 LiquidAI 的公布值；自带 CLI、交互对话与 OpenAI 兼容 server，支持流式输出与 reasoning 内容。Apache-2.0。

### 10. [codician-team/diffinery](https://github.com/codician-team/diffinery) · ⭐ 10 · Rust / TypeScript · 外部开源 · 10-25 建仓

跑在你自己 Cloudflare 账号里的开源 GitHub 替代品——Git 托管、PR、代码评审、Issues、Releases、容器镜像与 CI 一整套，并且是「agent 优先」的。

要点：现有 `.github/workflows/*.yml` 原样兼容，marketplace actions 也照跑，一个 Worker 同时供 Web UI、git over HTTPS、GitHub 兼容的 REST 与 GraphQL API 和 MCP server；每个仓库是一个独立 Durable Object 加自己的 SQLite，横向扩展不共用数据库；Claude Code、Codex、Cursor 这些编码 agent 拥有自己的账号，角色上限受所属人约束，每次 commit 记录它代表谁，且 agent 的 check 结果永远不满足 required checks；自带 MCP server 并已上架官方 MCP Registry，另有 Claude Code / Codex 插件、VS Code / Cursor / Windsurf / JetBrains 扩展与 `gh` 兼容。Apache-2.0。

### 11. [InternRobotics/InternW0](https://github.com/InternRobotics/InternW0) · ⭐ 6 · 外部开源 · 10-20 建仓 / 10-23 首次推送（延续上期）

### 12. [theorem-labs/oss-verify-proofs](https://github.com/theorem-labs/oss-verify-proofs) · ⭐ 147 · 外部开源 · 10-22 建仓（延续上期）

Anthropic 与 Theorem 的机器检查证明库：让内核证明「这个 fuzz 目标在给定界限内找不到能触发失败的输入」。

要点：README 当前口径是 25 个库的 60 个入口点已有证明，用 Rocq 9.2.0 检查；证明陈述在 LPS 里——一个运行 RISC-V 二进制的 Linux 进程形式化模型；对象是编译产物而非源码：静态 riscv64 程序，clang 20.1.8 对 musl 构建，每个入口点最多四套（plain、ASan、UBSan、ASan+UBSan），证明的是「在界限内的每个输入上，带 sanitizer 的构建与普通构建行为一致，且 sanitizer 从不报错」；仓库自己写明 LPS 是尽力而为且不完备的——证明的好坏上限就是 LPS 的好坏。
