### 1. [NVIDIA/auto-ontology](https://github.com/NVIDIA/auto-ontology) · ⭐ 8,689 · Python · 日榜第 2（连续第 3 天，位次 -1）

给企业数据搭语义本体层，让 LLM 生成的 SQL 可校验、可溯源。

要点：Python 框架，前端 Next.js 16 + React 19 + TypeScript + Tailwind 4 + Prisma，后端 FastAPI + Python 3.12+ + LangChain，存储 PostgreSQL 17 + pgvector，可选 HashiCorp Vault 存凭据；本体含三类实体——业务术语（带描述、同义词、映射列）、经评审的 SQL 属性（度量/表达式）、表间关系（含从键与数据推断的桥表），模型用 Apache Ossie YAML 导入导出；查询链路是意图分类与实体抽取 → 向量检索候选术语/列/SQL 属性 → 生成 SQL → 校验过滤值与语法并修复 → 执行并返回答案、SQL 与推理步骤，覆盖不足时会明说无法从已连数据回答；推理依赖 NVIDIA NIM 端点，按 REASONING / NON_REASONING / EMBED / RERANK 四种角色分别配 endpoint + API key + model，对外暴露只读 MCP（FastMCP）、REST（`POST /api/chat/completions`，SSE 流式，x-api-key 鉴权）与 CLI，另附 setup / management / query 三个 agent skill。需 NVIDIA API key（nvapi- 前缀）与数据库凭据；README 提示 3001/3002 后端端口应留在私有网络，ingest/delete/reset/compile 等摄取接口无独立鉴权，示例默认口令须在启动前全部替换，仓库标注暂不接受外部贡献。

### 2. [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) · ⭐ 63,414 · JavaScript · 日榜第 17（隔 12 天回榜）

多阶段安全审计技能，用独立验证者交叉核验每条发现。

要点：六阶段流程——侦察产出 architecture.md 与 coverage-ledger.json，按 ledger 单元分派隔离 hunter 并用 coverage critic 找盲区，每个候选交给全新 verifier 尝试证伪，写出 findings.json，再用新 agent 独立复核源码主张、重大替换后再次独立验证，最后由已验证记录派生 REPORT.md、FINDINGS-DETAIL.md、NEEDS-VALIDATION.md；发现三态严格区分，confirmed 需完整源码溯源与有界观察结果，needs_validation 只指明未决事实且不带严重性，rejected 记录被证伪的候选，findings.json 按 report-schema.json 校验，父流程跑两个零依赖校验器 validate-coverage-ledger.cjs 与 validate-findings.cjs；覆盖目标类型包括原生/内存安全/二进制/内核、LLM 应用、HTTP 与认证协议、浏览器端代码、依赖与 CI/CD 发布签名、基础设施 IAM 容器 serverless、RPC 序列化队列、资源耗尽、租户隔离与备份恢复、桌面移动端与本地 IPC；重复跑同一仓库设计为累积式，前次 ledger 与发现用于聚焦缺口、重查变更代码，保留仍有效证据而不把过期或未决工作当作已覆盖；安装走 `npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit`（加 `--global` 为用户级），默认输出到 `~/security-audit-skill/<repo-name>/run-<N>`。需要支持工具调用与并行子 agent 的编码 agent、Node.js，以及带禁网、白名单环境、资源配额与限定写入路径的 OS 级沙箱；README 称单次运行约只能发现重复运行合并总量的约一半漏洞，缺少这些控制时不执行目标代码、线索一律降级为 needs_validation。
