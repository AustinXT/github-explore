# 开源 AI 日报 11.18：2 小时训完 64M 小模型，Agent 编排层集体上新

## 📌 今日导读

11-17 的日榜 15 席里 12 席是 AI（非 AI 的 3 席是 Docker 管理工具 arcane、Cursor 插件规范 cursor/plugins 和框架 svelte）。这一轮**新进榜的 AI 项目有 4 个**：腾讯 LoopForge 第 4 席、obra/superpowers 第 9 席、affaan-m/ECC 第 13 席、jingyaogong/minimind 第 14 席——其中 3 个本站已有深度报告，LoopForge 还没有。但今天真正的重心不在「新项目」本身，而在于**同一个工作层被四个团队从四个方向同时做了一遍**。

第一个看点在成本的量级。[jingyaogong/minimind](https://github.com/jingyaogong/minimind) 新进榜即第 14 席、65,843★，它把预训练、全量 SFT、LoRA、DPO、RLAIF、Agentic RL 到蒸馏的全流程压到 mini 数据集上约 1.21 小时预训练 + 1.10 小时 SFT，合计成本约 3 元人民币，模型是 64M 稠密、8 层、d_model 768、词表 6400。**「2 小时训完一个 LLM」这句话过去是营销，现在是可以照着 README 复现的账单。**

第二个看点在编排层。同一时间窗里，[腾讯 LoopForge](https://github.com/Tencent/LoopForge) 发 v0.4.0 并冲上日榜第 4 席，把 Codex、Claude Code、Cursor CLI 等 10 种编码 Agent CLI 编排成带人工卡点、检查点与审计轨迹的 SOP；[滴滴 helixharness](https://github.com/didi/helixharness) 开源把企业工程知识沉淀进仓库的编码 Agent 插件；[withcoral/coral](https://github.com/withcoral/coral) 做 Agent 的外部服务网关；[ruvnet/ruflo](https://github.com/ruvnet/ruflo) 发 v3.77.2。**四个项目解决的是同一个问题：Agent 的执行链路怎么被复用、被审批、被审计。**

第三个看点在记忆层与执行层同一天互相加固。[thedotmack/claude-mem](https://github.com/thedotmack/claude-mem) 在 11-18 03:11 UTC 发出 v16.0.0，首页从 5,138px 压到约 2,600px、列表从 195 行折成 5 行，同时**移除了 Observation TV 页面与 `CLAUDE_MEM_TV_TOKEN`**；同一天 [anthropics/claude-code](https://github.com/anthropics/claude-code) 的 v2.1.327 加了 `claude mcp add-json <name> -`，让 MCP server 的 JSON 从 stdin 读，令牌不必再落在命令行上。**一个在给记忆做减法，一个在给凭据做减法。**

### 1. [jingyaogong/minimind](https://github.com/jingyaogong/minimind) · ⭐ 65,843 · Python · 日榜第 14（新进榜）· 评分 7.4

**把「训一个模型」这件事的门槛，压到了三块钱。**

要点：覆盖预训练、全量 SFT、LoRA、DPO、RLAIF、Agentic RL 与蒸馏的完整链路；minimind-3 是 64M 稠密模型——8 层、d_model 768、4 个 KV 头、词表 6400；mini 数据集下预训练约 1.21 小时、SFT 约 1.10 小时，两项成本合计约 3 元；MoE 版本是 4 专家 top-1 路由、无共享专家，速度约慢 50%；导出侧同时支持 Transformers、llama.cpp、vLLM、Ollama、SGLang 与 OpenAI 兼容接口，Apache-2.0 许可。

**它的价值不在 64M，而在这条链路是完整的。** 大多数「两小时训模型」类项目只给你一个 pretrain 脚本，而这里把 DPO、RLAIF、Agentic RL 和蒸馏都放进了同一条可复现路径——**这正好补上小模型教程普遍缺失的后训练那一半。**

### 2. [Tencent/LoopForge](https://github.com/Tencent/LoopForge) · ⭐ 3,016 · Go · 日榜第 4（新进榜）· v0.4.0（11-17 14:30 UTC）· 评分 7.2

**它把「让人审批」写进了工作流定义，而不是塞在提示词里。**

要点：支持 10 种编码 Agent CLI 执行器（含 Codex、Claude Code、Cursor CLI 等）；SOP 引擎有 5 类节点——Agent、脚本、**人工卡点**、子 SOP 与预览构建；内置 4 个 SOP 模板，覆盖后端交付、前端交付、产品提案与缺陷修复；支持检查点、日志、工具轨迹、重试、暂停恢复与人工签署，默认端口 8090；v0.4.0 的改动集中在加固——Agent CLI 的配置写入被限制在 home 目录、仓库克隆 URL 不再携带凭据、SSH 仓库支持按主机指定 user key、定时任务 prompt 不再有长度限制、运行中的 workspace 可被编辑，SOP 沙箱内安装 Agent CLI 时密钥会被脱敏；提供 Web 工作区与 HTTP/MCP 接口，MIT 许可。

**「人工卡点」是一个节点类型，而不是一句提示词。** 这意味着审批可以排队、可以重试、可以留下轨迹——企业真正缺的不是「让模型停下来问一句」，而是「让停下来这件事本身有状态」。而在 3,016 星体量下就把凭据隔离和密钥脱敏做成默认行为，说明这类团队一开始就假设环境不可信。

### 3. [alibaba/open-code-review](https://github.com/alibaba/open-code-review) · ⭐ 53,610 · Go · 日榜第 3（一夜升 8 位）· v1.13.11（11-17 05:30 UTC）· 评分 6.9

**一夜升 8 位到第 3 席，它靠的不是模型，是确定性。**

要点：采用确定性工程 + 带工具 Agent 的混合架构，相关文件按评审单元隔离并发处理；除 `review` 外支持 `ocr scan` 全量文件或目录审计；官方基准覆盖 50 个热门开源仓库、200 个真实 PR、10 种语言，由 80+ 位资深工程师交叉标注出 1,505 个 ground-truth 问题，称相比 Claude Code 精确率与 F1 更高、token 用量约为其 1/9，但**召回率低于通用 Agent**——README 明确说这是「以召回换精确、主动选择少报」的取舍（均为官方自述数据）；v1.13.11 修复了一批边界问题——按分支过滤会话列表、多字节文件路径按 rune 边界截断、配置集中带点号的 MCP server 名、VS Code 端把部分失败与失败的评审显示为「失败」而非「No issues found」、ACP 报错信息里写明输入长度限制；`npm install -g @alibaba-group/open-code-review`，Apache-2.0 许可。

**「按 rune 边界截断」和「失败要显示为失败」这两条修复，都是在修同一件事：让工具的输出可以被信任。** 而把确定性的静态规则（空指针、线程安全、XSS、SQL 注入）和 LLM 的判断拆开跑，是把 code review 从「一次性对话」变成「可复跑的流水线」的关键一步。

### 4. [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem) · ⭐ 112,647 · TypeScript · v16.0.0（11-18 03:11 UTC）· 评分 6.8

**一个大版本，做的是减法。**

要点：v16.0.0 重做了 My Work 页面——首页从约 5,138px 压到约 2,600px，List 打开时从 195 行折成 5 行，My Rules 从 17,000px 以上压到约 4,400px；「需要你处理的事」置顶，只留一个橙色按钮；请求是一行一条，Idle 与 Shipped 各折成一行并带计数；回复框固定在进度行正下方，回复在途时「Reply here」会等待，避免一条消息被当成第二次付费轮次发到另一个会话；**Observation TV 页面及其只读远程访问被移除**（`/tv`、`tv.html` 与 `CLAUDE_MEM_TV_TOKEN` 设置一并删除，改用 `CLAUDE_MEM_LOCAL_API_TOKEN`）；每个页面按 390px 手机宽度适配，支持键盘与读屏，首帧前渲染主题；新增法语、韩语、土耳其语与中文翻译。同窗口的 v15.21.0 修了「claude-mem 会把 Claude Code 的 Code Mode 关掉」这一冲突（Code Mode 在 Claude Code 2.1.323+ 会拒绝启动挂钩 `tool.call` 的插件模块），auto-clear 恢复时改发带任务上下文的续跑提示而非裸 `continue`，触发点从 33% 提到 40% 上下文窗口。

**把记忆从「一个页面」变成「一份待办」，是 Agent 记忆层最容易走错的一步。** v16 砍掉 TV 页并把首页压掉一半高度，指向同一个判断：记忆的价值不在于看得多，而在于**被需要时能立刻浮上来**。而 Code Mode 那个冲突更值得记一笔——插件挂 `tool.call` 会让整个 Code Mode 起不来，这类「插件与新特性互相锁死」的问题，是 Agent 插件生态现在最真实的成本。

### 5. [withcoral/coral](https://github.com/withcoral/coral) · ⭐ 5,016 · Rust · 首次收录 · 评分 6.5

**它把「Agent 该能碰什么」做成了网关，而不是提示词。**

要点：Agent 通过工作区专属的 MCP URL 接入，提交的程序在**无网络的 V8 isolate 中执行**；策略网关在注入凭据前校验每一次底层调用，受限调用转入人工审批；成功的程序可保存为可复用自定义工具，也能发布为工作区共享工具；官方 34 任务基准称 token 降 37%、成本降 31%、完成时间降 29%（官方自述）；支持经 MCP/OpenAPI 接入 5000+ 数据库与 SaaS 工具；Apache-2.0 许可（`ee/` 目录另附许可）；近几日在把各处时间戳统一改写为 UnixNanos 的重构进行中，v1.8.0（11-13）之后仍在密集提交。

**「程序在无网络 V8 isolate 里跑，凭据由网关代持」这套结构，比让 Agent 直接拿到 token 更接近企业真正能签字的方案。** 它和 coral 的时间戳重构放在一起看也很说明问题——一个正在做安全边界的项目，同时在把内部表示统一，这种收敛通常发生在准备对外交付之前。
