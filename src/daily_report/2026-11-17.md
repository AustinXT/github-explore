# 开源 AI 日报 11.17：3 个新进榜，大牛连收 2 个 Agent 沙箱

> 开源 AI 日报 · 2026-11-17 · 数据源：GitHub Trending + 大牛 Star 快照 + 本站 803 篇报告

## 📌 今日导读

11-16 的日榜 15 席里 12 席是 AI（非 AI 的 3 席是 Docker 管理工具 arcane、中国历史交互地图 jiangshan-map 和框架 svelte）。真正新进榜的 AI 项目只有 3 个——但今天的重心不在「新项目」，而在**执行层和默认值正在被整体改写**：榜外 24 小时里有 6 个项目发版，大牛侧则有一个人同窗口连收了两个「替 Agent 重做执行沙箱」的仓库。

第一个看点在执行层。白名单里的 Tobi Lütke 连收两条，都是「让 Agent 跑代码，但不用 fork 进程」：[TheUncharted/zapcode](https://github.com/TheUncharted/zapcode) 用 Rust 重写了一个 TypeScript 解释器——oxc 解析 → 自有 IR → 约 50 条指令的栈式字节码 → VM 执行，冷启动 2µs，README 里直接写着这是 MCP 工具调用的替代；[everruns/bashkit](https://github.com/everruns/bashkit) 更极端，把 167 个 Bash 命令全部用 Rust 重写、执行留在宿主进程内，默认文件系统是虚拟的、网络需白名单。**两条合起来是一句判断：Agent 工具调用的成本结构变了——从「起一个进程」变成「跑一段字节码」。**

第二个看点在推理栈的默认值。[vllm-project/vllm](https://github.com/vllm-project/vllm) 在 11-16 23:22 UTC 发出 v0.34.0：Model Runner V1 被移除、V2 成为唯一 GPU runner（V1 的 logits processors 需要迁移），`--block-size` 默认从 16 改成 64，`gpu_memory_utilization` 默认改成 1.0，可扩展 KV cache 默认开启。**默认参数就是政策——这一版会直接改变很多人的显存账和压测结论。**

第三个看点在 3 个新进榜的 AI 项目，全是「给 Agent 装上手」的工具。[mvanhorn/last30days-skill](https://github.com/mvanhorn/last30days-skill) 由 Lyft 联合创始人 Matt Van Horn 打造，新进榜直接第 9 席、68,043★，把 Reddit、Hacker News、X、YouTube、Polymarket 等源的近 30 天讨论聚合成带引用的简报；[google-research/paper-orchestra](https://github.com/google-research/paper-orchestra) 是 Google Research 的多智能体论文写作流水线；[kajisho5/ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) 把 42 个 FFmpeg 操作做成带类型化 schema 的工具包并配 MCP server，不需云服务与 API key。

### 1. [vllm-project/vllm](https://github.com/vllm-project/vllm) · 榜外发版 · v0.34.0（11-16 23:22 UTC）· 评分 7.6

这一版把三个默认值同时翻了过来，而这三个默认值恰好是过去两年所有部署教程的前提。

要点：Model Runner V1 被移除，V2 成为唯一 GPU runner，`VLLM_USE_V2_MODEL_RUNNER=0` 直接启动失败，V1 的 logits processors 需迁移到 `vllm.v1.worker.gpu.sample.logits_processor`；双 batch 重叠现已支持投机解码与 DCP；`--block-size` 默认由 16 改为 64，`gpu_memory_utilization` 默认 1.0（ROCm 仅保留 10.0，移除 ROCm 7.2 wheel）；可扩展 KV cache 默认开启——CUDA/ROCm 下按预热与 CUDA graph 捕获后的实际空闲显存定容，MiniMax-M3 在 H200 上从 433K 提升到 672K token，但 H200 并发 128 时 TPOT 可能上升 6–18%，可用 `--gpu-memory-utilization 0.9` 或 `--no-enable-extensible-kv-cache` 退回旧行为；性能侧 Step5 在 4×GB200 上解码最高 1.95×，GLM-5.3-Flash 输出吞吐 1.6×，MI355X 并发 1–8 交互性提升 35–57%；新增 10 个模型（含 Mistral Large 4、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe、Unlimited-OCR-2），CUDA wheel 体积减少约 82MB（25%）。

**官方同时给出了退路，这是好设计——但退路要你自己记得用。** 显存账、TTFT/TPOT 基线、投机解码路径，三条都建立在旧默认值之上；照抄旧教程压测的人会同时撞上「上下文变长了但 TPOT 变慢了」和「显存被吃满」两件事。

### 2. [anthropics/anthropic-sdk-python](https://github.com/anthropics/anthropic-sdk-python) · 榜外发版 · v2.9.0（11-16 16:47 UTC）· 评分 7.2

这一版最值得看的地方是它收紧的方式：不是加功能，是**缩小 Agent 能碰到的范围**。

要点：Windows 下目录名改为精确比较，经过悬空符号链接的文件工具与上传路径会被完全解析，memory 文件只经校验后的路径读取，指向 `/memories` 之外的符号链接不再出现在列表中；内置搜索在无 ripgrep 时最多 30 秒 CPU 时间，只在 PATH 的绝对条目中查找 rg（Windows 走 rg.exe），**跳过位于 agent 可写目录（workdir / allowed_roots）内的 rg 二进制与 rg 配置文件**，且 rg 子进程不再继承 `ANTHROPIC_*` 环境变量；新增 Claude Tag Bundle 的 Update 接口与 RBAC 角色读取端点（响应回传 instructions、错误码字段）；会话线程终止后 max_idle 倒计时继续运行，已终止线程不再执行或产出工具调用（拒绝调用、非本 runner 拥有的工具除外），已归档会话统一上报为 terminated；skill 下载或解压失败时保留已有 skill 目录。

**这三条指向同一个假设：Agent 的工作目录不可信。** 在一个「目录里可能被写进一个恶意 rg」的模型下，把 PATH 解析权和环境变量继承权都收回来，是唯一稳的做法。

### 10. [TheUncharted/zapcode](https://github.com/TheUncharted/zapcode) · ⭐ 99

被 1 位大牛 star：Tobi Lütke（11-16）

要点：四段流水线——oxc_parser 解析并剥离类型 → 生成 ZapcodeIR → 编译为约 50 条指令的栈式字节码 → VM 执行；冷启动 2µs，基准覆盖完整 parse→compile→execute 路径且不做缓存也不预热；核心 crate 中没有 unsafe 块，对抗测试套件含 19 类攻击共 65 个用例；核心 crate 不含文件系统、网络与环境能力，解析阶段直接拒绝 import、require、eval、动态 import、globalThis 与 global；外部函数通过「VM 挂起 → 宿主执行 → 结果回注」的方式接入；支持快照与恢复，典型 Agent 快照小于 2 KB、执行内存约 10 KB；资源上限可配——内存 32 MB、执行时间 5 秒、调用栈 512 帧、堆分配 100000 次、JSON 嵌套最深 64 层；不支持 Promise.race 与任意 npm 包，正则可解析但不可执行；MIT 许可，`npm install @unchartedfr/zapcode`。

**它的定位写得最直白：MCP tool calling 的替代品。** 把「让 Agent 执行一段不可信 TypeScript」从「起一个 Node 进程」改成「跑一段 50 条指令的字节码」，启动成本从毫秒级降到微秒级，安全边界从进程隔离改成解释器能力裁剪。**这是把隔离层做薄、做硬的一种思路。**

### 11. [everruns/bashkit](https://github.com/everruns/bashkit) · ⭐ 390

被 1 位大牛 star：Tobi Lütke（11-16）

要点：所有命令用 Rust 重写（167 个内置命令），执行留在宿主进程内，**不做进程派生**；默认文件系统为虚拟的，网络访问需白名单，每个解释器实例相互隔离；目标符合 IEEE 1003.1-2024 Shell Command Language，支持变量展开、管道、重定向、函数、数组、通配符、here-document 与 trap；默认限额——1 万条命令、单循环 1 万次、总循环 100 万次、函数深度 100、stdout/stderr 各 1 MiB、文件系统 100 MB、单文件 10 MB、1 万个文件、解析超时 5 秒、AST 深度 100；提供 InMemoryFs、OverlayFs、MountableFs 三种文件系统后端，带静态脚本分析、快照恢复、LLM 工具契约与多租户隔离；静态分析覆盖 17 类共 280+ 威胁；支持 Rust、C、Python、JS/TS、WASM 绑定，可选 git/python/typescript/sqlite/realfs 特性；MIT 许可，`cargo add bashkit`。

**它的目标不是「跑得快」，是「跑在别人的租户里也安全」**——虚拟文件系统 + 网络白名单 + 硬性资源上限 + 多租户隔离，四件套一起才是 SaaS 里跑 Agent 需要的最小安全面。
